# Serialized release index publication

Implement a per-track transactional release index. A publisher supplies the `latest` revision it observed before building. Under one serialized publish operation, reject stale bases, reject duplicate revisions, and commit a complete immutable version snapshot plus its `latest` pointer together. A build failure must leave both generation and published index unchanged. Concurrent publishers that observed the same base must not both consume/replace shared temporary output: exactly one may publish and the other must learn that its base is stale. Tracks advance independently. Published revision file lists are immutable snapshots: retries, duplicate revisions, failed builds, and later publications must never rewrite an older revision's files. Validate the observed base before reporting a duplicate or build failure. Preserve the visible API and use safe Rust only.
